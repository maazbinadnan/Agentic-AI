# Initial Audit Report: CAZ User Needs & System Scope

## 1. Scope Analysis

### Explicitly Stated Needs
- Users want to breathe better air, with fairness and minimal disruption.
- Users need to understand CAZ (Clean Air Zone) schemes, their impact, and affected areas/times.
- Users need to check vehicle compliance and avoid unnecessary charges.
- Users need to make payments easily and quickly.
- Users need to find out about exemptions and apply for them.
- Users need to understand differences between CAZs.
- Users need technical support.
- Users need to find alternatives to paying charges.
- Users need clear signposting for CAZ boundaries.
- Users need to apply for refunds and manage PCNs.

### Implicit Needs & Assumptions
- System must be accessible and usable for all user types (including those with disabilities).
- System must be reliable, performant, and GDPR compliant.
- Users may interact via mobile or desktop.
- Users may need multi-language support (not stated, but common for public services).
- Users may need notifications/reminders (e.g., payment due, PCN received).
- System should prevent errors (e.g., unnecessary payments).

## 2. Gaps & Ambiguities
- No explicit mention of user authentication or account management.
- No details on integration with external payment providers or vehicle databases.
- No mention of how users are notified of CAZ changes or PCNs.
- No explicit accessibility requirements.
- No mention of data retention or audit logging.
- No details on support for business/fleet users vs. individuals.

## 3. Technical Constraints
- Must support multiple CAZs with different rules and charges.
- Must be fair, equitable, and minimize negative impact.
- Must provide clear, actionable guidance at each step.

## 4. Recommendations
- Clarify if user accounts are required or if the system is fully anonymous.
- Specify accessibility standards (e.g., WCAG 2.1 compliance).
- Confirm if notifications (email/SMS) are required.
- Define integration points (vehicle database, payment gateway, PCN system).
- Clarify support for business/fleet users.
- Confirm language/localization requirements.

## 5. Next Steps
- Proceed to formalize user needs, functional and non-functional requirements, user stories, and UI mockups as per the BA deliverables structure.
